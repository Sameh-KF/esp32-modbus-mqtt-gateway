# Resolved SHT20 wiring fault — 25 October 2026

**Status: resolved.** The sensor's white RS485 B conductor was detached inside its enclosure. Repairing the conductor restored communication without changing the firmware or sensor settings.

| Stage | Observation |
|---|---|
| Before repair | Direct ESP32/XY485 reads timed out with no response bytes |
| Inspection | White B conductor detached from the sensor PCB |
| Repair | Conductor reattached; yellow=A+ / white=B− restored |
| Verification | Same firmware and FC04 read profile: **10/10 valid replies, 0 failures**, all CRCs matched |
| Subsequent integration | Physical sensor data reached MQTT and the Node-RED dashboard |

The controlled before/after result localized the direct sensor communication fault to the broken connection. No baud-rate, address or register-map change was needed. Failed reads remained errors rather than being converted into zero measurements.

See the [successful standalone read test](SHT20_PHYSICAL_VALIDATION_2026-10-25.md) for the response frames and the [hardware gateway report](HARDWARE_GATEWAY_VALIDATION_2026-10-25.md) for the completed end-to-end run.
