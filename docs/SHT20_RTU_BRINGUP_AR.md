# إعداد واختبار حساس SHT20 عبر Modbus RTU

**الحساس يعمل في المشروع عبر ESP32-S3 وواجهة XY485.** هذه الصفحة تجمع إعدادات القراءة والتوصيل وأدوات الاختبار المنفصلة. نتائج التشغيل الفعلي في [تقرير الحساس](SHT20_PHYSICAL_VALIDATION_2026-10-25.md) و[تقرير المشروع الكامل](HARDWARE_GATEWAY_VALIDATION_2026-10-25.md).

## الإعداد الذي ثبت عمليًا

| الإعداد | القيمة |
|---|---|
| البروتوكول | Modbus RTU |
| عنوان الجهاز | 1 |
| الاتصال | 9600 baud، 8N1 |
| Function Code | FC04 — Read Input Registers |
| أول سجل خام / عدد السجلات | `0x0001` / 2 |
| سجل الحرارة | `0x0001`، عدد int16 بإشارة، القسمة على 10 للحصول على °C |
| سجل الرطوبة | `0x0002`، عدد uint16، القسمة على 10 للحصول على %RH |
| الطلب | `01 04 00 01 00 02 20 0B` |

تتحقق أدوات الاختبار من CRC ومن مطابقة عنوان الجهاز والرد قبل تحويل القيم، ولا ترسل أوامر كتابة أو تغيير إعدادات.

## توصيلات المشروع

| الطرف | التوصيل |
|---|---|
| GPIO17 | مدخل TXD في XY485 |
| GPIO18 | مخرج RXD في XY485 |
| 3V3 في ESP32 | VCC في XY485 |
| GND في ESP32 | GND في XY485 وسالب تغذية الحساس |
| أحمر الحساس | موجب تغذية الحساس الاسمية 12 V |
| أسود الحساس | سالب التغذية / المرجع المشترك |
| أصفر الحساس | A+ |
| أبيض الحساس | B− |

تُنجز التوصيلات مع فصل التغذية. لا تُوصل تغذية الحساس إلى 3V3 أو GPIO في ESP32. محول USB-to-RS485 غير مطلوب في مسار المشروع النهائي.

## اختبار مستقل بمحول USB-to-RS485

يمكن استخدام الأدوات الموجودة في المستودع لتشخيص حساس من الحاسوب. صِل A وB وGND إلى الأطراف المقابلة، مع بقاء تغذية الحساس منفصلة؛ اترك طرف 5V في المحول دون توصيل. استخدم Modbus master واحدًا فقط أثناء الاختبار.

من جذر مجلد المشروع، استبدل COM14 بمنفذ المحول الفعلي:

```powershell
powershell -NoProfile -File .\tools\Test-Sht20.ps1 -ListPorts
powershell -NoProfile -File .\tools\Test-Sht20.ps1 -Port COM14 -Samples 3
```

يعرض البرنامج TX وRX بالصيغة الست عشرية والقياسات الصحيحة، ثم يغلق المنفذ. بين الطلبات ثانيتان، والمهلة الافتراضية 1500 ms. لا تفتح المنفذ نفسه في برنامج آخر بالتزامن.

للبحث المحدود عن إعدادات جهاز غير معروف:

```powershell
powershell -NoProfile -File .\tools\Find-Sht20.ps1 -Port COM14
```

الأداة ترسل 22 طلب قراءة فقط وتتوقف عند أول رد مطابق وسليم CRC، وتحفظ سجل JSON في `logs/`. نتائج المسح مرشحات اتصال؛ تُراجع خريطة السجلات قبل اعتمادها كقياسات.

## تفسير النتائج

- **رد مطابق وCRC صحيح:** الاتصال والبروتوكول يعملان ضمن إعداد الاختبار.
- **مهلة دون بايتات:** لم تصل استجابة مقروءة؛ افصل بين احتمال انقطاع الخط أو التغذية أو اختلاف إعدادات الجهاز باختبار موجّه.
- **CRC mismatch أو رد مبتور:** يُرفض الرد.
- **Modbus exception:** احتفظ بكود الاستثناء والرد الخام لتشخيص الطلب.
- **فشل القراءة:** لا تُستبدل القيمة بأصفار؛ يبقى الخطأ منفصلًا عن آخر قراءة صحيحة.

## التحقق البرمجي

اجتازت أداة القراءة 15 حالة اختبار، تشمل الإطار المرجعي، الحرارة السالبة، الصفر، RH=100%، CRC فاسدًا، إطارًا مبتورًا، عنوانًا غير متوقع، Modbus exception، قيمة رطوبة غير مقبولة والمهلة. واجتازت أداة البحث المحدود 44 حالة اختبار باستخدام بديل برمجي للمنفذ التسلسلي. اختبارات الأدوات موجودة في `tests/`.

تعتمد الإعدادات أعلاه على الاستجابات الفعلية للحساس. ملف `SHT20-Sensor-Modbus-RS485.pdf`، الصفحات 2–5، كان مرجعًا أوليًا؛ CRC يُحسب برمجيًا بدل نسخ أمثلة الطلبات.

مراجع الواجهات: [SerialPort.GetPortNames](https://learn.microsoft.com/en-us/dotnet/api/system.io.ports.serialport.getportnames)، [SerialPort.ReadTimeout](https://learn.microsoft.com/en-us/dotnet/api/system.io.ports.serialport.readtimeout)، [Modbus application protocol](https://www.modbus.org/file/secure/modbusprotocolspecification.pdf).
