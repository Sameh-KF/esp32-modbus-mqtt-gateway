# ESP32-S3 Modbus RTU → MQTT Gateway

برنامج `industrial_gateway` مبني باستخدام ESP-IDF 6.1. يقرأ حساس SHT20 عبر RS485 كل ثانيتين، وينشر الحرارة والرطوبة إلى MQTT لعرضهما في Node-RED. تعمل قراءة الحساس بصورة مستقلة عن الاتصال بالشبكة.

## التوصيلات

| ESP32-S3 / الحساس | واجهة XY485 |
|---|---|
| ESP 3V3 | VCC |
| ESP GND وسالب تغذية الحساس | GND |
| GPIO17، UART1 TX | TXD، مدخل الوحدة |
| GPIO18، UART1 RX | RXD، خرج الوحدة |
| أصفر الحساس | A+ |
| أبيض الحساس | B− |

الأحمر والأسود في كابل الحساس متصلان بموجب وسالب تغذيته الخارجية. تُغذّى ESP32 عبر USB، وتُغذّى XY485 من 3.3V. لا تُوصل تغذية الحساس الخارجية إلى ESP32 أو XY485. افصل التغذية قبل تغيير الأسلاك. محول USB↔RS485 أداة تشخيص اختيارية؛ مسار التشغيل النهائي يستخدم ESP32 وXY485.

إعداد SHT20: العنوان 1، سرعة 9600، صيغة 8N1، الوظيفة FC04، بداية السجل الخام 1، وعدد السجلات 2. الطلب: `01 04 00 01 00 02 20 0B`. يُفسّر سجل الحرارة كعدد signed 16-bit، وسجل الرطوبة كعدد unsigned 16-bit، ثم تُقسم القيم على 10. يتحقق parser من طول الرد والعنوان والوظيفة وCRC ونطاق الرطوبة.

## البناء والتشغيل

من مجلد `firmware/gateway` وفي طرفية ESP-IDF:

```powershell
idf.py set-target esp32s3
idf.py menuconfig
idf.py build
idf.py -p COM9 flash monitor
```

استخدم `set-target` عند إعداد نسخة جديدة، واستبدل `COM9` بمنفذ اللوحة المحلي. في VS Code يمكن تنفيذ الخطوات نفسها بأوامر إضافة ESP-IDF. أوقف أي Monitor آخر يحتجز المنفذ قبل Flash.

اضبط بيانات الشبكة محليًا في `Gateway WiFi` و`Gateway MQTT`. عنوان الوسيط مثل `mqtt://192.168.1.105:1884`، مع استبدال IP بعنوان الكمبيوتر الحالي. يمكن ضبط خادم NTP محلي في `Gateway clock`؛ الافتراضي `pool.ntp.org`.

الاعتماد `espressif/mqtt` مثبت على 1.1.0. الإعدادات الافتراضية: Flash بسعة 16MB، وضع DIO/80MHz، وقسم factory بحجم 2MB. Console هو UART0 على GPIO43/44 بسرعة 115200. ملفات `sdkconfig` وكلمات المرور وملفات البناء مستبعدة من المستودع.

## MQTT ومعالجة القراءات

| Topic | QoS | Retain |
|---|---:|---:|
| `industrial/gw-01/telemetry` | 1 | لا |
| `industrial/gw-01/availability` | 1 | نعم |
| `industrial/gw-01/diagnostics` | 1 | لا |

تُنشر `online` عند الاتصال، ويُضبط LWT على `offline` مع Keepalive قدره 15 ثانية. معرف العميل `industrial-gw-01`؛ استخدم معرفًا مختلفًا لأي ناشر تجريبي يعمل بالتوازي.

كل محاولة قراءة تحمل `seq`، ويتغير `boot_id` عند إعادة التشغيل. القراءة السليمة تحمل `quality: good` والقيم الفعلية؛ الفشل يحمل `quality: bad` و`values: null` وسببًا مثل `NO_RX` أو `CRC`. لا تُحوّل الأخطاء إلى قياسات صفرية.

يُسجل UTC عند التقاط القراءة بعد مزامنة SNTP. قبل المزامنة تبقى قراءة الحساس متاحة، لكن `time_valid` يساوي `false`. يستخدم Dashboard وقت الالتقاط وعمر العينة للفصل بين القراءات الحديثة والقديمة. راجع [عقد MQTT](../../docs/MQTT_CONTRACT.md).

## الانقطاع وإعادة الاتصال

يُحفظ آخر ناتج قراءة فقط في RAM، وتستمر القراءة أثناء انقطاع الشبكة. يبدأ النشر بعد إعادة الاتصال بعينة جديدة، دون إعادة إرسال تراكم من القراءات القديمة. أقصى عمر محلي قبل النشر 2500ms.

توجد رسالة QoS1 واحدة قيد الانتظار لجميع المواضيع، وتُنشر `online` قبل telemetry. حجم outbox هو 2048 bytes، وتنتهي رسائله بعد 3000ms. عند انقطاع جلسة MQTT يُنشأ عميل جديد بعد تفريغ outbox السابق، مع تأخير إعادة اتصال يصل تدريجيًا إلى 30 ثانية. تعرض diagnostics عدادات القراءة والاتصال وPUBACK والرسائل المتروكة والذاكرة المتاحة.

الإصدار معد لشبكة LAN موثوقة مع مصادقة MQTT. لا يتضمن OTA أو TLS في هذا الإصدار.
